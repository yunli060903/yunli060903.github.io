java反序列化入门篇-03-动态代理

在这一篇中想记录一下学习代理的原理和作用，但在基础篇-01中已经用代码有一个大致的了解了，后面尽可能减少重复

java的代理模式

先简单来说一下什么是代理吧，代理的本质是不修改目标类原有代码的前提下，在目标方法执行前后增加额外逻辑（增强）。 有一个代理对象，持有目标对象引用；外部调用者只和代理对象打交道，由代理对象转发请求给真实目标。而在java的代理模式中存在静态代理和动态代理两种代理模式。

静态代理

那就有人在想了，有没有什么办法可以保留静态代理的优点但又抛弃其缺点，于是动态代理就诞生了

动态代理

我们原本在静态代理中是写死了一个类一个代理，但在动态代理的概念中，我们的代理并不专门为某一个类服务而是动态定义的。那这个时候我们应该代理什么呢，代理的是每个类都要实现的接口，不得不佩服前人的思维。

动态代理的意义

有了动态代理，我们就不需要给每一位房东都配备一个中介，而是哪位房东需要中介我们就为哪位房东服务，运行时由 JVM 动态生成代理字节码，内存中创建代理 Class，不需要提前写代理.java文件。大大减少了我们的代码量。同时我们对于真实类的改动频率可以极大被减少，公共方法只需要在代理类进行添加或修改就好。

并且一个代理还可以实现多个接口，动态代理其实远不止眼前这点知识，但我们学反序列化到这足以，讲多容易偏题，后面会单开一篇来写一下。

动态代理在java反序列化中的作用

动态代理最妙的地方就在于invoke 方法在动态代理当中会自动执行。

我们假设一下如果存在一个能够利用漏洞的类B.f，我们将入口类定为A。最为理想的情况是A[O]，存在O.f，那么此时我们只需传入B赋值给O，即可调用B.f，当然这只是我们说的最为理想的情况，现实中几乎不可能遇见。

动态代理的出现为反序列化找寻触发链提供了新方案和新思路，让其不必完全拘泥于同名函数的调用，把触发点放在 readObject 或者 invoke 两个位置。且JDK原生代理类大多实现Serialize，对于我们的反序列化研究提供了更多便利。
