0x01 前言

本来学习差不多了打算再整体翻翻，但突然看到ysoserial的CC6链突然多了一个我没见过的类HashSet，就有点懵了，但其实也就是多了一层包装，将HashSet作为入口类，但为了学习的完整性，还是再开一篇来讲解一下吧

0x02 环境

  • jdk8u65
  • Maven 3.9.2
  • Commons-Collections 3.2.1

0x03 HashSet分析

先贴一下ysoserial的思路

相比于我们前面所学的CC6链其实也就是换了个入口类，那我们先去看一下HashSet.readObject()

这里根据对象里元素数循环读取变量依次put，这里的话我们就可以调用HashMap.put()

但这里HashSet的构造函数是无法传入我们我们指定的HashMap对象的，它自己会new一个HashMap对象。但我们需要传入TiedMapEntry对象作为key去调用hashcode方法。所以这里我们去找到了HashSet.add()

给个提醒：这里两个put方法的利用目的并不相同，后者是用于构造我们完整的序列化对象，前者是为了触发链子。

下面来尝试编写一下EXP吧

HashSettest.java

但我们在这里发现并没有成功，其实这里和我们在研究CC6的问题一样

HashSet.add()调用了HashMap.put()，此时我们用的是无害ConstantTransformer，就正常写入key-value，随着序列化一起进入流中，在反序列化时被读出，但此时就被containsKey读取到是存在的key，就直接寄寄了。

依旧remove即可解决

0x04 ysoserial版EXP编写

仔细去看了一下ysoserial的脚本，发现虽然思路大致相同，但其并不是通过add方法构造序列化对象的，而是直接暴力把 Node 的 key 改成 TiedMapEntry对象，也是一种新的思路，我们来学习一下

尝试编写EXP的时候改了好几遍，真是改麻了，最后还是借助ai调错才调出来

ysoserialEXP.java

我们在put键值对的时候其实是new了一个Node对象，放入table中，当然前提是这个键值对是原本不存在的

然后会调用putVal方法，这里面实现了创建新Node节点和插入table的功能

所以我们最终是要反射修改Node对象中的key值，这里我们原本写的是hashSet.add("foo");，所以放的是foo，我们现在反射修改为TiedMapEntry对象

但这里在研究的时候感觉挺奇怪的，这里造序列化对象的方法也太麻烦了，
